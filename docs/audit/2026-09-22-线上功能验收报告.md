## 四、发现的问题

### 4.1【已修复】商品图片全部 404（严重）

**现象**：图片上传返回 200、MinIO 容器内直连该对象也是 200，但浏览器按返回的
`http://…:8080/img/campustrade/…png` 取图是 404。

**根因**：`deploy/nginx/campustrade.conf` 里后加的静态资源正则
`location ~* \.(png|jpg|js|json|…)$` **优先于**前缀 location `/img/`、`/api/`
（nginx 匹配顺序：最长前缀 → 正则）。于是图片请求被截走，去本地静态目录找文件。
伪装性很强：`/img/campustrade/`（不带扩展名）反而正常，容易误判为 MinIO 故障。

**修复**：`/img/` 与 `/api/` 加 `^~` 前缀修饰符；复验
`/img/…png → 200 image/png`，`/api/school/list → 200`，静态资源长缓存不受影响。
已记入 `deploy/README.md` 第五节第 9 条。

### 4.2【待决策】评价的鉴权范围不一致

- `GET /api/reviews/goods/{goodsId}`：**公开**（在 `SecurityConfig` 的 permitAll 名单里）；
- `GET /api/reviews/user/{userId}`：**需要登录**（不在名单里，匿名请求 401，带令牌 200）。

功能本身正常，但"看商品的评价不用登录、看某人的评价要登录"是否是有意设计，需要你确认。
若希望两者一致（都公开或都要登录），改 `SecurityConfig` 一行即可。

### 4.3【已知限制】真实校园邮箱通道未打通

生产 SMTP 仍是占位账号，真实邮件发不出去。当前用**演示模式白名单**覆盖演示需求
（`demo-verify@<学校后缀>`，见 `deploy/README.md` 第七节）。
要恢复真实链路，把发信账号与授权码给我即可。

## 五、非缺陷说明（避免误判）

1. **未完成校园认证不能发布商品**：返回 400"发布二手商品前请先完成校园身份认证"，
   这是设计规则（认证是发布的硬前置），不是缺陷。
2. **中文关键词直接拼在 URL 上会 400**：原始非 ASCII 字节出现在请求行不合 HTTP 规范，
   Tomcat 直接拒绝；浏览器与 `curl --data-urlencode` 都会自动编码，正常使用不受影响。
3. **AI 返回的是本地规则结果**：`DeepSeek API Key` 未配置时，
   `AiGoodsServiceImpl` 会走"本地规则 / 本地算法降级"（返回结构化描述、关键词分类、
   按原价折算的估价区间），这是设计内的优雅降级，不是假数据。
4. **演示模式开启时每次启动有 WARN 日志**：这是 `VerifyDemoGuard` 的刻意设计
   （点名白名单邮箱，防"忘了关"）。
