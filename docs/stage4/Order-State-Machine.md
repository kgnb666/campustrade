# Stage 4-A: 订单状态机设计 (Order State Machine)

- **所属模块**：交易状态引擎 (Transaction Lifecycle Engine)
- **核心目标**：定义严密、确定、不可逆转的订单状态流转模型与细粒度权限控制矩阵。

---

## 一、状态定义 (State Definitions)

| 状态枚举值 (Code) | 中文名称 | 业务语义与阶段说明 | 终态标识 |
| :--- | :--- | :--- | :---: |
| `WAIT_SELLER_CONFIRM` | **等待卖家确认** | 买家已发起交易请求，商品已被锁定，等待卖家确认接单或拒绝 | 否 |
| `WAIT_MEET` | **等待校园面交** | 卖家已确认接单，双方按照约定地点与时段准备线下见面验货交割 | 否 |
| `COMPLETED` | **交易完成** | 线下验货无误，当面完成货物交割与结算，双方确认完成，信用沉淀 | **是 (终态)** |
| `CANCELLED` | **交易取消** | 交易在完成前被买家取消、卖家拒绝/取消或超时终止，商品释放回售 | **是 (终态)** |

## 二、状态流转图 (State Machine Diagram)

```
                       [买家发起意向]
                             │
                             ▼
                 ┌───────────────────────┐
                 │  WAIT_SELLER_CONFIRM  │
                 │   (等待卖家确认接单)   │
                 └───────────┬───────────┘
                             │
            ┌────────────────┼────────────────┐
    [卖家确认接单]     [买家主动取消]     [卖家拒绝接单]
            │                │                │
            ▼                │                │
   ┌─────────────────┐       │                │
   │    WAIT_MEET    │       │                │
   │  (等待校园面交)  │       │                │
   └────────┬────────┘       │                │
            │                │                │
       ┌────┴────┐           │                │
[当面验货完成]  [协商取消]     │                │
       │         │           │                │
       ▼         └───────────┼────────────────┘
┌─────────────┐              ▼
│  COMPLETED  │       ┌─────────────┐
│ (交易终态)  │       │  CANCELLED  │
└─────────────┘       │ (取消终态)  │
                      └─────────────┘
```

## 三、操作权限控制矩阵 (Role-Based Action Matrix)

| 操作动作 (Action) | 当前允许状态 (Source State) | 目标状态 (Target State) | 允许执行者 | 业务校验与前置条件 |
| :--- | :--- | :--- | :---: | :--- |
| **创建订单** (`create`) | 无 (商品状态必须为 `ON_SALE`) | `WAIT_SELLER_CONFIRM` | **买家 (BUYER)** | 1. 买家已通过校园实名认证；<br>2. `buyer_id != seller_id`；<br>3. 商品无其他未完结活动订单。 |
| **卖家确认** (`confirm`) | `WAIT_SELLER_CONFIRM` | `WAIT_MEET` | **卖家 (SELLER)** | 1. 仅限对应订单的卖家；<br>2. 可选填写回复留言或微调面交建议。 |
| **买家取消** (`cancel_by_buyer`) | `WAIT_SELLER_CONFIRM` 或 `WAIT_MEET` | `CANCELLED` | **买家 (BUYER)** | 1. 仅限对应订单的买家；<br>2. 必须填写取消原因 `cancel_reason`；<br>3. 若在 `WAIT_MEET` 阶段取消，提示需与卖家沟通。 |
| **卖家拒绝/取消** (`cancel_by_seller`) | `WAIT_SELLER_CONFIRM` 或 `WAIT_MEET` | `CANCELLED` | **卖家 (SELLER)** | 1. 仅限对应订单的卖家；<br>2. 必须填写原因（如“物品已被同班同学买走”等）；<br>3. 自动释放商品。 |
| **确认完成** (`complete`) | `WAIT_MEET` | `COMPLETED` | **买家或卖家 (BOTH)** | 1. 线下当面验货付款完成；<br>2. 仅限买家或卖家操作；<br>3. 自动将商品标记为 `SOLD`，双方信用 `trade_count + 1`。 |

## 四、非法状态跃迁防御策略 (Illegal Transition Guards)

状态机遵循**“白名单准入机制”**，任何不在状态转移矩阵中的流转请求将被严格拦截并返回标准业务异常：

### 1. 终态不可逆转 (Terminal Immutability)
- `COMPLETED`（已完成）：
  - 严禁调用 `cancel`、`confirm`、`complete`；
  - 抛出：`400 "订单已完成交易，状态不可变更"`。
- `CANCELLED`（已取消）：
  - 严禁重新激活或再次确认；
  - 抛出：`400 "订单已取消终止，不可重复操作"`。

### 2. 禁止跳跃流转 (No State Skipping)
- 严禁从未确认状态 `WAIT_SELLER_CONFIRM` 直接跃迁至 `COMPLETED`；
  - 必须由卖家显式确认接单，进入 `WAIT_MEET` 约定线下见面后，才能完成交易。

### 3. 并发重复操作幂等
- 卖家重复点击确认接单：
  - 若订单状态已是 `WAIT_MEET`，幂等返回成功，防止重复触发通知；
- 重复点击取消：
  - 若已是 `CANCELLED`，幂等提示已取消，不重复释放商品库存。
